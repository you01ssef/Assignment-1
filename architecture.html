01

Frontend

The part you see

HTML, CSS, and JavaScript create the portfolio, sign-in forms, notebook, and local assistant. User content is displayed as text to prevent HTML injection.

02

Web server

The entry point

Node.js and Express serve public pages and API routes. A public deployment needs an HTTPS host or reverse proxy in front of the server.

03

Application layer

The rules in the middle

Express route handlers check input, verify sessions, enforce permissions, and encrypt notes before calling the database.

04

Database

A small, persistent store

SQLite stores users, sessions, rate-limit counters, and encrypted notes. Prepared statements separate SQL commands from user input.

05

Authentication

Who are you?

Registration and sign-in use a username and password. Each password is stored as a salted scrypt hash. Login attempts are rate limited.

06

Authorization

What can you access?

Visitors can read public pages. Signed-in users can access only their own notes. Every note query checks the user ID on the server.

07

Encryption

Keep private content private

Note text uses AES-256-GCM encryption at rest. Production must use HTTPS for data in transit. Password hashing is one-way; it is not encryption.

08

Session management

Remember a verified sign-in

A random session token goes in an HttpOnly, SameSite=Strict cookie. Only its hash is stored in SQLite. Sessions expire after 30 minutes and are revoked at logout; production cookies are Secure.

09

Input validation

Check before trusting

The server validates usernames, password lengths, note lengths, and IDs. JSON bodies are limited to 8 KB. Origin and CSRF token checks protect changes.

FOLLOW A REQUEST

What happens when I save?

  1. The browser sends your note with a session cookie and CSRF token.
  2. The server checks the origin, session, token, and note length.
  3. The server encrypts the text and saves it with your user ID.
  4. Only your authenticated session can retrieve or delete that note.
KEEPING THE SCOPE SMALL

Built for a class project.

No admin dashboard, paid AI service, or complicated infrastructure. The two access levels are public visitor and signed-in note owner.

The local assistant uses curated answers. The 2FA widget illustrates a concept; actual sign-in uses a password. Usernames and timestamps are not encrypted.

See it in action →
Hosting matters. GitHub Pages serves the public portfolio and assistant. To use accounts and notes, run the included Node server. A public server requires HTTPS, a persistent data folder, and a private encryption key.
