01

Frontend

HTML, CSS, and JavaScript. Notes and chat messages are displayed as plain text.

02

Web server

GitHub Pages serves the site over HTTPS. No server installation is needed.

03

Application layer

JavaScript runs the live notebook, validation, encryption, assistant, and calculator in the browser.

04

Database

The live demo uses encrypted browser storage, not a hosted database. The optional Node backend contains SQLite for the full database requirement.

05

Authentication

The demo unlocks encrypted notes with a passphrase-derived key. Real server authentication exists only in the optional backend.

06

Authorization

Browser UI checks illustrate access flow but are not trustworthy server authorization. The optional backend enforces note ownership in SQL.

07

Encryption

Web Crypto derives an AES-256-GCM key using PBKDF2-SHA-256, 600,000 iterations, and a random salt. Each save uses a new random IV. GitHub Pages uses HTTPS.

08

Session management

The live demo keeps its key in memory and locks after 15 minutes, on refresh, or manually. The optional backend has expiring HttpOnly cookie sessions.

09

Input validation

Notebook names, passphrases, and note lengths are checked. The math parser does not execute JavaScript. Client checks are demonstrative; backend validation remains in the optional server.

For the assignment: The browser demo does not replace a server database or enforce real multi-user authorization. The original Express/SQLite implementation remains in the repository if your instructor requires those components to run on a server.

Follow one save

Your browser validates the note, encrypts the notebook using your unlocked key, then stores ciphertext. Your passphrase and key are not saved. Locking clears the key and displayed notes.

Know the limits

No syncing, password recovery, or secure server accounts. Anyone controlling this browser or its scripts can interfere. Clearing site storage deletes your notes. Never use this classroom demo for secrets.
