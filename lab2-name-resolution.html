NETWORK CONFIGURATION AND CONNECTIVITY

Lab 2.1: Name Resolution

Lab A: localhost

Simulated example: These system details and results are sample values. The tests were not performed.

1. System information

Windows 11 Pro, version 24H2. Computer name: LAB-PC. Account: local administrator.

2. Open the command prompt

On Windows, open Start and type cmd. On macOS, open Applications → Utilities → Terminal.

3. Network settings and loopback

Use ipconfig /all on Windows or ifconfig -a on macOS.

Sample network settings
IPv4 address:    192.168.1.100
Subnet mask:     255.255.255.0
Default gateway: 192.168.1.1
DNS server:      192.168.1.1
DHCP enabled:    Yes

Sample result for ping 127.0.0.1: four packets sent, four received, 0% loss, response times below 1 ms.

Sample result for ping ::1: four packets sent, four received, 0% loss, response times below 1 ms.

On macOS, use ping6 ::1 for IPv6. Both addresses refer to the local computer. They test the same basic function using different IP versions. Successful loopback replies do not prove that the internet works.

4. Ping localhost

Sample result: ping localhost resolved to ::1, with four replies and 0% packet loss.

The operating system recognizes localhost through its name resolver, local configuration, and built-in handling. It can resolve to 127.0.0.1 or ::1.

5. Examine the hosts file

Windows: C:\Windows\System32\drivers\etc\hosts
macOS: /private/etc/hosts

Sample Windows entries
# localhost name resolution is handled within DNS itself.
# 127.0.0.1 localhost
# ::1 localhost

Lines starting with # are comments. They provide instructions or inactive examples. In this example, Windows handles localhost internally. macOS commonly includes active localhost entries and 255.255.255.255 broadcasthost.

6–7. Add names and save

For the simulated computer, add these lines and save with administrator privileges:

192.168.1.1 winserv
192.168.1.100 me

These entries map names to IP addresses on this computer only.

8. Ping me

Sample result: ping me resolved to 192.168.1.100. Four packets sent, four received, 0% loss, and response times below 1 ms.

9. Ping winserv

Sample result: ping winserv resolved to 192.168.1.1. Four packets sent, four received, 0% loss, and an average response time of 2 ms.

A real gateway may block ping. A timeout does not necessarily mean name resolution failed; check the address displayed.

10. Could the hosts file be exploited without administrator privileges?

Normally, standard users cannot change it. Incorrect file permissions could let someone redirect a name to the wrong server. An attacker could also trick an administrator into editing the file.

11. Display the DNS cache

On Windows, run ipconfig /displaydns. The cache stores name-resolution records to reduce repeated lookups.

Sample cache excerpt after adding the hosts mappings
me
    Record Type:     1
    Time To Live:    86400
    Data Length:     4
    Section:         Answer
    A (Host) Record: 192.168.1.100

winserv
    Record Type:     1
    Time To Live:    86400
    Data Length:     4
    Section:         Answer
    A (Host) Record: 192.168.1.1

Record type 1 means an IPv4 address record. These sample records come from the hosts file.

The older macOS procedure uses sudo killall -INFO mDNSResponder. The logging location and Console steps depend on the macOS version; /var/log/system.log is not reliable for every newer version.

Conclusion

Loopback tests check local networking. The hosts file maps names to IP addresses locally, and the DNS cache temporarily stores name-resolution information.
