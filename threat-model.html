THINK LIKE A DEFENDER

What could go wrong?
Plan for it.

A simple STRIDE threat model for the portfolio and its security lab: protect accounts, private notes, content integrity, and availability.

This model covers the Node application. The GitHub Pages version serves public content only. Publishing permissions and hosting account settings still need to be managed separately.
S

Spoofing

Someone tries to sign in as another user.

CONTROL / LIMITATION

Salted password hashes, generic login errors, rate limits, and expiring sessions reduce the risk.

T

Tampering

An attacker submits a forged request or edits a note ID.

CONTROL / LIMITATION

Origin and CSRF checks protect writes. Server-side ownership checks prevent cross-account deletion.

R

Repudiation

Someone denies changing the site or deleting a note.

CONTROL / LIMITATION

Git history tracks code changes. This small app has no full audit log; that remains a limitation.

I

Information disclosure

A leaked database reveals private study notes.

CONTROL / LIMITATION

Note content is encrypted with AES-256-GCM. Keys and the database are excluded from public files and Git. Usernames and timestamps remain readable.

D

Denial of service

Repeated requests consume server or browser resources.

CONTROL / LIMITATION

Authentication rate limits, body-size limits, a 50-note quota, and capped chat history reduce resource use. Host-level protection is still needed for a public site.

E

Elevation of privilege

A user tries to access another user’s notebook.

CONTROL / LIMITATION

The server derives ownership from the session, never from a user-supplied owner ID. There is no public admin role.

The trust boundary

Everything from the browser is untrusted. Hiding a button is not authorization: the server verifies sessions, checks ownership, and validates input before using SQLite.

What’s still outside scope?

Real MFA, password recovery, a full audit trail, and large-scale abuse protection. HTTPS depends on the deployment host. Encryption does not protect against an attacker who controls both the server and its key.
