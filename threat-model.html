Real questions.

A simple STRIDE review of the live browser notebook.

Spoofing

An attacker guesses a notebook passphrase. PBKDF2 slows guessing, but there is no server login or enforced rate limit.

Tampering

AES-GCM detects changes to encrypted notes. Someone with browser access can still delete or replace stored data.

Repudiation

The live demo has no audit trail. Git history tracks website changes, not notebook actions.

Information disclosure

Notes are encrypted at rest. XSS, malicious extensions, or a compromised page can read notes while unlocked. Text-only rendering reduces injection risk.

Denial of service

Limits of 50 notes, 1,000 characters per note, and capped chat history reduce browser load. Storage can still be cleared or exhausted.

Elevation of privilege

Browser UI checks are not a security boundary. Real multi-user authorization requires the optional server backend.

The repository also contains the original Express/SQLite backend with server-side access checks. The live GitHub Pages notebook is a separate browser demonstration.
